# AI-SNAB

Локальное (offline-first) веб-приложение для сопровождения закупок: ведёт кейсы, поставщиков и документы, помогает контролировать комплектность и готовит основу для автоматизации (OCR → извлечение полей → локальный чат-ассистент без утечки данных наружу).

✅ Что уже сделано (MVP-ядро)

✅ Step 1 — Инфраструктура + UI-скелет

✅ Web UI (FastAPI + Jinja2) со страницами /ui/*
Зачем: чтобы сотрудник работал “в браузере”, без Excel/папок, и чтобы все сущности были видимы сразу.

✅ Docker Compose (offline-first): Postgres + MinIO + Redis + Nginx + App + Worker
Зачем: одна команда запуска → всё локально, данные не уходят наружу, легко разворачивать на любом ПК/сервере.

✅ Health-проверки: /health, /health/db, /health/storage
Зачем: быстро понимать, где проблема (приложение/БД/хранилище), без “угадывания”.

## Архитектура (локально)

- **web-proxy (Nginx)**: проксирует UI/API на app
- **app (FastAPI)**: UI + API + бизнес-логика
- **database (Postgres)**: сущности (Suppliers/Cases/Documents/…)
- **minio (S3)**: хранение файлов документов
- **redis**: очередь задач для worker
- **ollama**: локальный LLM для чата и генерации
- **worker (RQ worker)**: обработка документов асинхронно (пока без OCR)

## Быстрый старт

### 1) Запуск

```bash
cd infra
docker compose up -d --build
```

**Важно:** При старте контейнера `app` автоматически применяются миграции Alembic (`alembic upgrade head`). Это происходит до запуска uvicorn, поэтому схема БД всегда актуальна.

### 2) Проверка сервисов

```bash
docker compose config --services
docker compose ps
```

Ожидаются сервисы: `database`, `minio`, `redis`, `ollama`, `app`, `worker`, `web-proxy`.

### 3) Доступ

Приложение доступно через Nginx на порту ....:

- **UI**:      http://localhost:..../ui
- **Health**:  http://localhost:..../health
- **DB**:      http://localhost:..../health/db
- **Storage**: http://localhost:..../health/storage

### 4) Seed демо-данных

```bash
docker compose exec app python -m app.scripts.seed_demo
```

**Примечание:** Seed работает как на чистой БД (после `docker compose down -v`), так и на существующей БД. Миграции применяются автоматически при старте, поэтому seed не должен падать с ошибками типа `UndefinedColumn`.

Seed создаёт (без дублей):
- поставщики (демо)
- кейсы (демо)
- категории документов (активные/архивные, включая SUPPLIER_*)
- шаблон чек-листа PROCUREMENT_V1 (из Word документа)
- профили поставщиков с демо-данными (ОКВЭД, оборудование, сертификаты)

## Ollama (локальный LLM)

### Настройка

Ollama автоматически поднимается при `docker compose up -d --build`. Сервис доступен на порту `127.0.0.1:11434` (только локально, не извне).

### Проверка работы Ollama

```bash
# Проверка версии Ollama
curl http://localhost:11434/api/version
```

Ожидаемый ответ:
```json
{"version":"..."}
```

### Использование /api/chat

**Веб-интерфейс (рекомендуется):**
- Откройте http://localhost:8080/ui/chat в браузере
- Введите сообщение и отправьте
- Можно указать `case_id` или `supplier_id` для контекста

**API эндпоинт:** `POST /api/chat`

**Запрос:**
```json
{
  "message": "Расскажи о кейсе",
  "case_id": "uuid-кейса",  // опционально
  "supplier_id": "uuid-поставщика"  // опционально
}
```

**Ответ:**
```json
{
  "response": "Ответ от LLM на основе данных из БД",
  "context_used": {
    "case": {...},  // если указан case_id
    "supplier": {...}  // если указан supplier_id
  }
}
```

**Важно:** `/api/chat` — это POST эндпоинт. Для удобного тестирования есть веб-интерфейс: http://localhost:8080/ui/chat

Также можно использовать curl, Postman или PowerShell (см. примеры ниже).

**Примеры использования:**

1. **Общий вопрос (без контекста):**
```bash
# PowerShell
$body = @{message="Привет, как дела?"} | ConvertTo-Json
Invoke-WebRequest -Uri http://localhost:8080/api/chat -Method POST -ContentType "application/json" -Body $body

# Linux/Mac
curl -X POST http://localhost:8080/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "Привет, как дела?"}'
```

2. **Вопрос о кейсе:**
```bash
curl -X POST http://localhost:8080/api/chat \
  -H "Content-Type: application/json" \
  -d '{
    "message": "Что не хватает для завершения закупки?",
    "case_id": "ваш-uuid-кейса"
  }'
```

3. **Вопрос о поставщике:**
```bash
curl -X POST http://localhost:8080/api/chat \
  -H "Content-Type: application/json" \
  -d '{
    "message": "Расскажи о поставщике",
    "supplier_id": "ваш-uuid-поставщика"
  }'
```

**Guardrails:**
- Если указан `case_id` или `supplier_id`, но данные не найдены в БД, API вернёт ответ: "Нет данных в системе. Отсутствует: ..."
- LLM получает только факты из БД, не выдумывает информацию

### Настройка модели

По умолчанию используется модель `qwen2.5:7b-instruct`. Чтобы изменить модель, установите переменную окружения:

```bash
# В .env файле
CHAT_MODEL=llama3.2:3b
```

**Важно:** Модель должна быть загружена в Ollama перед использованием:
```bash
# Загрузка модели (выполнить один раз после первого запуска)
docker exec aisnab_ollama ollama pull qwen2.5:7b-instruct
```

**Проверка загруженных моделей:**
```bash
curl http://localhost:11434/api/tags
```

Если модель не загружена, `/api/chat` вернёт ошибку. После загрузки модели (может занять несколько минут, ~4.7 GB) эндпоинт будет работать.

### Инструменты агента

Доступны через `app.services.agent_tools`:

- `validate_procurement(case_id)` — проверка готовности закупки (возвращает `{ok, missing[], blockers[]}`)
- `export_zip(case_id, mode)` — экспорт кейса в ZIP (пока заглушка)
- `generate_doc(template_key, context)` — генерация документа по шаблону (пока заглушка)

## Документы: загрузка, хранение, статусный pipeline

### Как работает upload

1. Пользователь выбирает категорию и файл
2. Backend сохраняет файл в MinIO:
   - Для кейсов: `cases/<case_code>/<category_key>/<uuid>_<filename>`
   - Для поставщиков: `suppliers/<supplier_id>/<uuid>_<filename>`
3. В Postgres создаётся запись `documents` (метаданные + статус)
4. Документ ставится в очередь Redis/RQ
5. Worker обрабатывает задачу:
   - переводит `IN_PROGRESS` → `DONE` (или `ERROR`)

### Как проверить вручную

1. Открой http://localhost:8080/ui/cases
2. Нажми "Открыть" у кейса → увидишь чек-лист
3. Или нажми "Документы" у кейса
4. Загрузи небольшой файл (.pdf / .png / .jpg)
5. Сразу увидишь `IN_PROGRESS`
6. Через 1–2 секунды обнови страницу → станет `DONE`

Логи worker:
```bash
docker compose logs -f worker
```

## Система закупок

### Workflow закупки

1. **Создание закупки** (`/ui/cases`)
   - Создаётся без выбора поставщика
   - Статус: "DRAFT (не активирована)"

2. **Основание закупки (стартовый пакет)**
   - Первый блок на странице закупки
   - Для каждого обязательного пункта:
     - Номер документа
     - Дата документа
     - Прикреплённый документ
     - Статус (TODO/DONE/NA) + комментарий
   - Кнопка "Активировать закупку" (только при заполнении всех обязательных пунктов)

3. **Активация закупки**
   - Валидация: все обязательные пункты основания должны иметь номер, дату и документ
   - После активации открываются секции анализа рынка

4. **Анализ рынка** (доступно после активации)
   - **Параметры закупки**: тип, предмет, этап процедуры
   - **Кандидаты и ранк-анализ**: добавление кандидатов, автоматический расчёт ранка
   - **Запрос КП (RFQ)**: журнал отправки запросов с подтверждениями
   - **Коммерческие предложения (КП)**: добавление КП, автоматический расчёт НМЦ
   - **НМЦ и валидация**: средняя цена, коэффициент валидации (≤33%)
   - **Проверка СБ**: статусы проверки службы безопасности
   - **Выбор победителя**: только при APPROVED от СБ

5. **Чек-лист процедуры** (ниже workflow)
   - Остальные пункты чек-листа (без основания)
   - Секции I–VI, группировка, прогресс
   - Блок "Проверьте закупку на ошибки"
   - Выбор пункта ЕПоЗ

### Возможности чек-листа

- **Шаблон из Word**: автоматический парсинг `docs/checklist_procurement.docx`
- **Секции I–VI**: группировка по секциям, сворачиваемые блоки
- **Прогресс**: "Выполнено: X / Y обязательных"
- **Фильтры**: по статусу (ALL/TODO/DONE/NA)
- **Статусы**: TODO, DONE, NA с комментариями
- **Привязка документов**: каждый пункт может иметь прикрепленные документы кейса
- **Блок ошибок**: отдельный блок "Проверьте закупку на ошибки" с подсветкой рисков
- **ЕПоЗ**: выбор пункта ЕПоЗ (6.6.2.1, 6.6.2.2, 6.6.2.3 (1), 6.6.2.3 (5))

### Использование

1. Создай закупку: `/ui/cases` → "Добавить закупку"
2. Заполни основание: номер, дата, документ для каждого обязательного пункта
3. Активируй закупку: кнопка "Активировать закупку"
4. Работай с анализом рынка: кандидаты, RFQ, КП, НМЦ, СБ
5. Выбери победителя (после APPROVED от СБ)
6. Заполняй чек-лист процедуры

## Карточка предприятия (поставщик)

### Возможности

- **12 секций данных**:
  1. Реквизиты (юр.данные + адреса)
  2. Контакты
  3. Деятельность (описание, продукция, отрасли)
  4. ОКВЭД (коды по одному в строке)
  5. Производство/мощности/оборудование (summary + детальная таблица)
  6. Персонал (численность по категориям + ключевые специалисты)
  7. СМК/сертификаты (checkbox + детальная таблица)
  8. ГОЗ (опыт, допуски)
  9. Опыт поставок (контракты, референсы)
  10. Реквизиты банка
  11. Подписант (ФИО, должность, основание)
  12. Документы поставщика (загрузка + список)

- **Экспорт контекста**: JSON для генерации документов по шаблону
- **Постепенное заполнение**: все поля optional, можно заполнять частями

### Использование

1. Открой список поставщиков: `/ui/suppliers`
2. Нажми "Карточка" у поставщика
3. Заполняй секции по мере необходимости
4. Загружай документы поставщика (устав, ЕГРЮЛ, сертификаты и т.д.)
5. Экспортируй контекст: кнопка "Экспорт контекста (JSON)"

## Troubleshooting

### 502 Bad Gateway (nginx)

Проверь контейнеры:
```bash
docker compose ps
```

Посмотри логи app и web-proxy:
```bash
docker compose logs app --tail 200
docker compose logs web-proxy --tail 200
```

Проверь, что app отвечает напрямую:
```bash
curl http://localhost:8000/health
```

### Документы не переходят в DONE

Worker должен быть Up:
```bash
docker compose ps
docker compose logs worker --tail 200
```

Если worker не может импортировать модуль — проверь WORKDIR/команду запуска в compose.

### Чек-лист не появляется в кейсе

Проверь, что шаблон создан:
```bash
docker compose exec app python -m app.scripts.seed_checklist
```

Проверь логи:
```bash
docker compose logs app --tail 200
```

#### Как использовать

**1. Загрузка шаблона в MinIO:**

Создайте bucket `aisnab-templates` (создаётся автоматически при старте) и загрузите шаблон:

```bash
# Через MinIO UI (http://localhost:9000)
# Или через mc (MinIO Client):
mc alias set local http://localhost:9000 minioadmin minioadmin
mc mb local/aisnab-templates
mc cp templates/NMC_REFERENCE.docx local/aisnab-templates/templates/NMC_REFERENCE.docx
```

**2. Создание записи Template в БД:**

```sql
INSERT INTO templates (id, key, doc_type, name, storage_key, is_active, created_at)
VALUES (
    gen_random_uuid(),
    'NMC_REFERENCE',
    'CASE',
    'Справка НМЦ',
    'templates/NMC_REFERENCE.docx',
    true,
    NOW()
);
```

**3. Использование через UI:**

1. Откройте страницу кейса: `http://localhost:8080/ui/cases/{case_id}`
2. В блоке "Генерация документов и экспорт" нажмите:
   - **"Сгенерировать справку НМЦ"** → создаст docx документ в документах кейса
   - **"Экспорт пакета (standard)"** → создаст ZIP архив с manifest.json

**4. Использование через API:**

```bash
# Генерация документа
curl -X POST http://localhost:8080/api/documents/generate \
  -H "Content-Type: application/json" \
  -d '{"case_id": "...", "template_key": "NMC_REFERENCE"}'

# Экспорт ZIP
curl -X POST http://localhost:8080/api/cases/{case_id}/export-zip \
  -H "Content-Type: application/json" \
  -d '{"mode": "standard"}'
```

**5. Формат шаблона:**

Шаблон docx должен содержать плейсхолдеры:
- `[[CASE_CODE]]` → код кейса
- `[[CASE_TITLE]]` → название кейса
- `[[NMC_AVG_PRICE]]` → средняя цена НМЦ
- `[[VALIDATION_COEFF]]` → коэффициент валидации
- `[[OFFERS_COUNT]]` → количество предложений
- `[[SELECTED_SUPPLIER_NAME]]` → имя выбранного поставщика

**6. Формат manifest.json в ZIP:**

```json
{
  "case_id": "...",
  "case_code": "...",
  "exported_at": "2025-12-13T18:00:00",
  "mode": "standard",
  "files": [
    {
      "document_id": "...",
      "filename": "...",
      "category_key": "...",
      "storage_key": "...",
      "sha256": "...",
      "size_bytes": 12345
    }
  ]
}
```
